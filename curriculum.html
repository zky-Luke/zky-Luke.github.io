MODULE 01

LLM 应用
基础

目标：会用 API 做出具有真实体验的 AI 功能，而不只停留在聊天框。

WEEK 01模型调用与流式 AI 对话+

学什么：消息结构、system prompt、温度、token、流式响应、结构化输出。

动手：用 React + 任意后端/Serverless API 做一个支持流式输出、停止生成和对话历史的聊天界面。

交付：ai-chat-starter GitHub 仓库 + 一篇「流式输出为什么要这样处理」的复盘。

验收：能中断生成；刷新后保留至少 3 轮对话；错误状态可见。

WEEK 02Prompt 与结构化输出+

学什么：少样本提示、约束、JSON Schema、重试与输出校验。

动手：做一个「文章/会议纪要 → 结构化行动项」工具，输出标题、优先级、负责人、截止时间。

交付：一个可复制结果的 Web 页面，以及 10 条失败样本和修复记录。

验收：结果可被前端直接渲染；错误 JSON 不会让页面崩掉。

WEEK 03模型选择、成本与体验+

学什么：快模型/强模型路由、上下文管理、缓存和用量统计。

动手：为前两周项目加入模型切换、耗时与 token 成本展示。

交付：一张 3 个模型在相同任务上的质量、速度、成本对比表。

验收：知道自己的产品一次请求大致花多少钱、慢在哪里。

MODULE 02

RAG
工程化

目标：做一个会引用来源、可评估、可改进的知识库助手。

WEEK 04文档解析与分块策略+

动手：导入 Markdown、PDF 或网页内容；对比固定长度、按标题和语义分块的效果。

交付：一个可查看原文片段与 chunk 的文档处理页面。

验收：能解释一条回答来自哪段原文。

WEEK 05检索、重排序与引用+

动手：接入向量库，实现 Top-K 检索、关键词混合检索、重排序和来源引用。

交付：一个个人知识库问答 Demo；每个回答都附可点击引用。

验收：回答不知道时能明确说不知道，而不是编造。

WEEK 06RAG 评测与迭代+

动手：自己制作 20 个问题集，记录检索命中率、引用正确性和回答质量。

交付：evals.md：问题集、基线结果、至少两次优化的前后对比。

验收：优化有数据依据，而不是“感觉回答更好了”。

MODULE 03

Agent
系统

目标：让模型可靠地使用工具，完成有状态、多步骤的工作。

WEEK 07工具调用与工作流+

动手：定义搜索、读取文件、计算三个工具；让 Agent 在界面中展示每一步调用。

交付：“研究助手”原型：输入主题 → 搜集 → 提炼 → 生成有来源的摘要。

验收：工具失败时 Agent 会重试或给出可理解的失败原因。

WEEK 08MCP 与外部能力连接+

动手：连接一个 MCP 服务，理解工具描述、权限边界与用户授权。

交付：一篇 MCP 实战笔记：服务连接方式、可调用工具、风险边界。

验收：敏感操作必须经用户确认，不能让 Agent 静默执行。

WEEK 09记忆、规划与可观测性+

动手：为 Agent 加会话摘要、任务状态和执行记录；区分短期上下文与长期偏好。

交付：一份 Agent Run Timeline：输入、决策、工具调用、结果和耗时。

验收：用户能看懂 Agent 做了什么，失败后能定位在哪一步。

MODULE 04

AI 产品
交付

目标：完成一个可以放进作品集、能让人试用的 AI 小产品。

WEEK 10选题与产品规格+

动手：选择一个垂直场景：知识库、学习、内容、效率或数据分析；写一页 PRD。

交付：目标用户、核心任务、边界、成功指标和 3 个关键界面线框。

WEEK 11全栈实现与部署+

动手：完成前端、API、数据存储、鉴权和生产环境错误处理。

交付：公开访问链接、README、环境变量说明和 3 分钟演示视频。

WEEK 12发布、复盘与作品集+

动手：找 3 位真实用户试用，收集任务成功率和反馈；只修最影响体验的问题。

交付：完整 Case Study：问题、方案、架构、评测、反馈、下一步。

验收：陌生人可以在 5 分钟内理解它解决什么，并自己完成一次任务。
